# Unique session names

**Ask.** "Do not allow duplicate names to agents, unless they are deleted.
Throw an error and spec out all edge cases."

**Summary**
- A session's display **name** (`Session.Name`, set by `rex new -name`,
  `rex name`, `r` / `:name` in the TUI and `::name` in the attach popup) is
  unique among the sessions in the daemon's store.
- A duplicate is refused with the new error code `name_taken`. The message
  names the session that holds the name: `name "fix auth" already in use by
  7d4f`.
- A name frees up only when its session leaves the store (delete).
- The daemon is the only authority. It checks under the store's write lock,
  in the same critical section that inserts a session or writes its name.

## Current behavior (v2.0.0, 2345b5c6)

A session has three labels:

| Field | Set by | Unique today | Role |
|-------|--------|--------------|------|
| `slug` | `NewSession.slug` (`rex new -slug`, or derived by the client), `Rename` intent (`rex rename`, `:rename`) | Yes, since the slug-selector work: `Store.AddUnique`, `Store.UpdateRename`, `bad_intent` `slug "x" already in use by <short>` | Selector for every command; ASCII-ish, no whitespace |
| `title` | `NewSession.title` (the task), `Rename` intent (`rex archive`) | No | Card title; free text |
| `name` | `NewSession.name` (`rex new -name`), `SetSessionName` intent (`rex name`, TUI `r`, `:name`, `::name`) | **No** | Display name shown instead of the slug; free text, max 64 runes, not a selector |

- `Rename` changes slug and/or title. `SetSessionName` changes the name.
  So "name" in the ask is `Session.Name`; slugs are already unique.
- `protocol.NormalizeSessionName` (`wire/protocol/name.go`) folds tabs and
  newlines to spaces, drops control, bidi and line-separator runes, collapses
  whitespace runs and trims. `""` means "no name".
- Names are never generated by rex. The TUI wizard and the new-agent page
  send no name (the wizard's name step was removed, see
  [P1](P1-name-model-and-skills-in-the-new-session.md)). Loop sessions
  (`daemon/server/loop.go`) send no name. Lua (`rex.sessions()`) reads names
  and cannot set them.
- Slugs are generated by clients: `rex new` (`deriveSlug` + `uniqueSlug`
  against the Hello snapshot), the TUI wizard, new-agent page and quick spawn
  (`deriveAgentSlug`, `-2` … `-999` against the board's sessions), and
  loops (`<loop>-<loop id>`). The daemon refuses a taken slug; it never
  rewrites one.
- Names are persisted in `sessions/<id>/meta.json` and restored with
  `Store.Add`, which checks nothing.

## Rule

`Store` refuses an operation that would leave two sessions in the store
with names that compare equal, where the operation is one of:

1. `AddUnique` (every `NewSession`, including loop spawns), and
2. `SetName` (every `SetSessionName`).

Nothing else writes a name.

## Edge cases and decisions

| # | Case | Decision |
|---|------|----------|
| 1 | Comparison | Both names go through `NormalizeSessionName` (trim, collapse whitespace, drop control and bidi runes), then each rune is mapped to the smallest rune of its `unicode.SimpleFold` orbit. This is Unicode **simple** case folding, the same equivalence as `strings.EqualFold`: `Fix Auth` = `fix auth` = `FIX  AUTH `, and the Kelvin sign `K` = `k`. Format runes (category Cf: zero-width space, ZWJ, soft hyphen, …) are ignored, so `ab` and `a​b` are equal. No NFC/NFKC normalization (precomposed `é` ≠ `e` + U+0301), no full folding (`ß` ≠ `ss`), no locale rules (Turkish dotted/dotless i follow the default orbit). The key is `protocol.SessionNameKey`; `protocol.SameSessionName` compares two names. The stored name keeps the user's case and spelling. |
| 2 | Empty or unset name | Never conflicts. Any number of sessions may have no name. Clearing a name (`rex name -clear`, empty `r`) always succeeds. A name that is only format runes (key empty) also never conflicts. |
| 3 | Which sessions hold a name | Every session in the store, whatever its state: queued, working, needs_input, done, failed, crashed, and marked done (retired but not yet cleared). Archived sessions too (archive is a title prefix). |
| 4 | What frees a name | Only removal from the store: `Delete` (`rex rm`, TUI delete and prune), and the retire sweep clearing a marked-done session after `retire_after_hours` (or the `Retire` ttl). A session being deleted holds its name until `SessionRemoved` (the store removal), which is after the child is stopped and the audit record is written. Marking done, completing, crashing, archiving or the daemon restarting does not free it. |
| 5 | Rename to its own current name, or a case/whitespace-only change of it | Allowed. `SetSessionName` compares against other sessions only, and a name equal (by the key) to the session's own current name is always accepted, even if a legacy duplicate (case 8) holds the same name. The patch is still broadcast. |
| 6 | Two concurrent `NewSession`s or `SetSessionName`s with the same name | Exactly one wins. The check and the write share `Store.mu` (write lock), the same lock that makes slugs unique. A `NewSession` also pre-checks before it reserves a concurrency slot or creates files, so most refusals have no side effects; the check under the lock is the one that counts. |
| 7 | Auto-generated names | rex generates none (see above), so nothing is renamed or suffixed by the daemon. Auto-generated **slugs** already pick a free `-2`, `-3`, … variant on the client against its snapshot, and that is unchanged. A slug race between two clients still ends in `bad_intent` `slug … already in use` (existing behavior, out of scope here). A future feature that generates names must pick a free variant itself (`<name> 2`, …) with `SameSessionName` against the snapshot. |
| 8 | Duplicates already on disk (older daemons, or a session dir that failed to delete and reloaded) | Loading never fails and never renames. Restore goes through `Store.Add`, which does not check. The daemon logs one warning per duplicated name at start (`daemon: duplicate name in restored sessions`, with the short ids). The duplicates stay until the user renames, clears or deletes one. Only new collisions are refused: renaming one of the holders to another taken name is refused, renaming it to its own name is allowed (case 5). |
| 9 | Resume, unretire, undone, complete | None of them change the name, and the session never left the store, so they never check and never fail with `name_taken`. Resume of a legacy duplicate works. |
| 10 | Hot restart (`Restart` hot) | The new image restores sessions from disk with `Store.Add` (case 8). Names survive unchanged. |
| 11 | Name vs. slug of another session | Separate namespaces. A name may equal another session's slug, and a slug may equal another session's name. Names are display text and not selectors; slugs are selectors and stay unique among slugs. (Open question for the user, see below.) |
| 12 | Workspaces | Global per daemon. A workspace board shows only its sessions, but a name held by a session in another workspace (or with none) is still taken; the error names that session's short id, which `rex ls` on the full board shows. The daemon's store has no per-workspace scope. |
| 13 | Error shape | New code `name_taken` (`protocol.ErrCodeNameTaken`), message `name "<stored name>" already in use by <short id>`, echoing the request `id`. Sent for `NewSession` and `SetSessionName`. On `NewSession` nothing is created (no session, no session dir, no concurrency slot). |
| 14 | CLI | `rex new -name` and `rex name` map `name_taken` to exit **5** (invalid args), like `bad_intent`. Text: `rex: spawn failed: name "x" already in use by 7d4f` and `rex: name "x" already in use by 7d4f`. Agent mode: `error code=5 kind=invalid_args …`. No client-side pre-check: the daemon decides. |
| 15 | TUI rename (`r`) | On enter the board checks its own session list first. A taken name keeps the editor open with the draft and shows `✗ name "x" already in use by 7d4f` on the editor line; typing clears the message. If the daemon refuses anyway (a race, or a session the board did not know yet) the `Error` (id `rename-<session id>`) reopens the editor with the draft and the message, when the board is not in another dialog; otherwise the message goes to the status line. |
| 16 | TUI `:name <text>` and attach `::name <text>` | Same local check; a taken name is a status-line error and nothing is sent. A daemon refusal is handled as in case 15: it reopens the board's rename editor with the text when no other dialog is open, else it goes to the status line. |
| 17 | TUI wizard and new-agent page | They send no name, so they can never get `name_taken`. Nothing to show; unchanged. |
| 18 | Older clients, newer daemon | An old CLI maps an unknown code to exit 1 and prints the message. An old TUI shows `daemon: name "x" already in use by 7d4f` on the status line, after closing the editor. Both still refuse; only the presentation differs. |
| 19 | Newer clients, older daemon (including pre-ack daemons) | The old daemon does not check, so duplicates are possible there. `rex name` waits for the `name` patch as before and succeeds. The TUI's local check still refuses names it can see on its board. Running `rex daemon restart` onto the new daemon enforces the rule (existing duplicates then follow case 8). |
| 20 | Fire-and-forget callers (intent without `id`) | The refusal is still an `Error`, with an empty `id` (the protocol rule for failures without an id). The name is unchanged. |
| 21 | `NewSession` with both a taken slug and a taken name | The slug is reported (`bad_intent`); it is checked first, as today. |
| 22 | Name too long, or only control characters | Unchanged: too long is `bad_intent`; a name that normalizes to `""` means no name (case 2). The uniqueness check runs after normalization. |
| 23 | The `name` of an unknown session | Unchanged: `unknown_session`. |

## Design

*Protocol (`internal/wire/protocol`).*
- `name.go`: `SessionNameKey(s string) string` and
  `SameSessionName(a, b string) bool` (false when either key is empty).
- `events.go`: `ErrCodeNameTaken = "name_taken"`.

*Store (`internal/daemon/state/store.go`).*
- `NameTakenError{Name, ID, ShortID}`, `Error()` = `name %q already in use by %s`.
- `nameHolderLocked(key, exceptID)`, like `slugHolderLocked`.
- `AddUnique` checks the slug, then the name, under `s.mu`.
- `SetName` takes `s.mu` (write) for the check and the write. It accepts a
  name whose key equals the session's current name's key.
- `CheckNew(slug, name)` returns the error `AddUnique` would return now
  (read lock), for the spawn pre-check.
- `DuplicateNames()` for the start-up warning.

*Server (`internal/daemon/server`).*
- `spawnSession`: `CheckNew` before `TryAcquireSession`; `AddUnique` stays the
  authority. On any `AddUnique` failure the session dir is removed (it may
  hold the hook file or staged skills).
- `handleNewSessionIntent` and `handleSetSessionName` map `*NameTakenError`
  to `name_taken`.

*Daemon start (`cmd/rex-daemon`).* Log `DuplicateNames()` next to
`DuplicateSlugs()`.

*CLI (`internal/surface/cli/session`).* `exitForCode`: `bad_intent` and
`name_taken` are exit 5; used by `awaitPatch` and `rex new`.

*TUI (`internal/surface/tui`).* `RenameState.Err`; `nameConflict` (local
check against `m.Sessions`); `Model.PendingName` (the last name sent, for
reopening the editor on a daemon refusal).

## Tests (written first)

- `state`: `AddUnique` and `SetName` refuse a taken name (case-insensitive,
  whitespace and format runes ignored); empty never conflicts; own name and
  case-only change allowed; done and retired sessions hold names; remove frees;
  concurrent `AddUnique` and concurrent `SetName` with one name: exactly one
  wins (`-race`); restored duplicates load and are reported; a legacy
  duplicate may keep its own name but not take another.
- `protocol`: `SessionNameKey` / `SameSessionName` table.
- `server`: handler tests for `NewSession` and `SetSessionName` (`name_taken`,
  message, nothing added); concurrent `NewSession` race over the socket; the
  `ack_test.go` table gains `name_taken` rows and stays green.
- CLI: `exitForCode`; e2e `session_names.txtar` (`rex new -name`, `rex name`
  conflicts exit 5, own-name case change, frees after `rex rm`).
- TUI: rename keeps the editor open with the error; daemon refusal reopens
  it; `:name` refuses locally.

## Open for the user

- Case 11: should a name also be refused when it equals another session's
  **slug** (the label the board shows for an unnamed session)? Not done: it
  would also mean refusing slugs that equal names, and clearing a name
  could then collide. Say if you want it.
- Case 7: the existing slug race (two clients deriving the same slug at the
  same moment) still errors instead of picking `-2`. Fixing it needs the
  daemon to pick the variant and clients to match the new session by the
  `Ack`'s `session_id` instead of by slug.
