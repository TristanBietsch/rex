rex v2.0.0 is the first release since v1: a rebuilt board, settings and
help, Lua config, folder trust, accurate READY and WAITING states, more
agents, and prebuilt binaries with a verifying installer.

## Highlights

- **Full-screen settings and help pages** (`S`, `?`) in the board's look,
  with a section list, search and a detail pane.
- **Themes**: a new default with a violet accent, bundled `dracula`,
  `tokyo_night` and `pantone_safe`, an `auto` theme, and your own theme
  files (`rex theme list|show|new`).
- **Accent color**: `accent_color` (or `:accent`, or the settings page with
  a swatch and live preview) sets the accent on any theme: a
  Pantone-inspired name, or `#hex`, `rgb()`, `hsl()`, `cmyk()`, `oklch()`.
  Too faint a color is adjusted until it reads.
- **Lua config**: `~/.config/rex/config.lua`, plus `.rex/config.lua` per
  workspace (display settings only, after `rex ws trust`).
- **Folder trust with guards**: `rex trust`, the wizard's trust line and
  `auto_trust_dirs` answer agents' folder-trust dialogs. Trust changes need
  a person at a terminal; `skip_permissions` is opt-in and only applies in
  trusted folders.
- **READY and WAITING you can rely on**: no flapping while subagents run,
  no false READY after notifications, compaction or Esc; a Waiting section
  for sessions busy on a shell command, subagent or web request.
- **Row icons**: fixed slots per row for finished, asks, what it waits
  on, loop turn, subagents and cost, right-aligned next to the age.
- **Green Ready, check-mark Done**: READY is a bright green `⚑`, DONE a
  calmer green `✓`; new state markers and agent icons, all one cell wide.
- **More agents**: Qwen Code, Cursor CLI, Grok Build, and Antigravity
  (`agy`) in place of the retired Gemini CLI.
- **Workspaces and loops**: per-workspace boards (`rex here`,
  `rex ws open`) and loop workflows with a turn counter on the row.
- **Undo**: `:undo` / `:redo` turn snapshots (`turn_snapshots`, off by
  default) and `uc` to undo marking a session done.
- **Usage**: a `:usage` page, a header usage meter and `rex usage`.
- **Waiting icon and screensaver settings**: `waiting_spinner`, plus the
  screensaver's counts layout, clock and drift (`screensaver_counts`,
  `screensaver_clock`, `screensaver_drift`).
- **Sound**: `master_volume` from 0 to 50, and audio settings apply live
  on every open board.
- **The hints footer**: key hints live on the bottom line (Done column keys
  too); `show_help_bar` hides only the hints.
- **Hot reload**: upgrade without killing sessions. `rex upgrade`
  hot-restarts the daemon in place (every agent keeps its process, PTY and
  screen) and swaps every open board into the new build. `rex daemon
  restart` is hot too; `-cold` keeps the old stop and start (Windows
  always restarts cold). `rex reload`, `:reload` and `R` in Settings reload
  every config layer, `init.lua` included.
- **New-agent page**: `n` opens a full-screen page with the agent, a
  multi-line task, context (large pastes, `@` paths, `ctrl+o` import),
  `$EDITOR` editing and folder trust on one screen.
- **Windows prompt safety**: agents installed as npm `.cmd` shims no longer
  get their task through `cmd.exe`, so `&`, `|` or `%VAR%` in a task can't
  run commands; over-long tasks are pasted instead of failing.
- **Render fixes**: popups stay straight with CJK and emoji text,
  multi-line pastes keep the help line on screen, short terminals keep the
  prompt, and prompts are typed without escape sequences.

The full list is in [CHANGELOG.md](https://github.com/TristanBietsch/rex/blob/v2.0.0/CHANGELOG.md).

## Breaking changes and migration

- **`master_volume` is 0–50** (default 40; was 0.0–1.0). `config.yaml`
  converts on load. In `config.lua`, `master_volume = 1` now means 1/50:
  write `50` for full volume. `rex doctor` points at the line.
- **Trust settings need a terminal.** `rex trust <folder>`, and
  `rex config set`/`reset` or `rex setup -auto-trust` of `skip_permissions`
  or `auto_trust_dirs`, exit 6 in agent mode, with `-o`, or in a pipe.
  Scripts that set these must run at a terminal or edit `config.yaml`.
- **`skip_permissions` is opt-in** (default off) and only applies in
  folders under `auto_trust_dirs`. Set it again if you relied on agents
  starting with `--dangerously-skip-permissions`.
- **`show_help_bar` off** hides only the key hints; errors and notices still
  show on the bottom line.
- **Glyphs changed**: READY is green with a `⚑` marker (was amber `◆`),
  DONE is a green `✓` (was `●`), failed `✗`, crashed `⊘`, loop `↻`; new
  agent icons (`claude` `✻`, `codex` `❀`, `antigravity` `✧`, `gemini` `⁑`,
  `ollama` `⌂`, `qwen` `❖`, `cursor` `◮`, `grok` `⍁`, `deepseek` `≋`, `kimi`
  `☾`, `echo` `∿`). Themes that set `needs` or `done` keep them. One space between an icon and its number
  (`⋔ 3`, `▴ 42m`), and row icons in place of the task text, right-aligned
  next to the age (set `row_icons` off for the old rows). No `✓ review`
  mark; the selected row has no background (the `▸` arrow marks it); the
  `∴ REX` logo is the theme's primary text color, not the accent. Custom
  themes that set glyphs may want a look.
- **"Needs you" reads "Ready"**, and the number keys follow four sections:
  `1` Ready, `2` Waiting, `3` Working, `4` Done.
- **Gemini CLI is replaced by Antigravity (`agy`).**
- **`color_scheme` is now `theme`**; the old key is still read.
- **CLI exit codes and parsing**: an unknown command exits 5; free text
  that starts with `-` needs `--` before it; `rex rm` without a terminal
  needs `-force`; declined questions exit 6; a selector that is one
  session's slug and another's id prefix exits 3.
- **Registry**: a user tool that relied on the built-in id switch for
  prompt delivery must set `prompt_args` or `prompt_paste`.
- **`init.lua`** owned by another user or writable by group or others is
  refused (`chmod go-w ~/.config/rex/init.lua`).
- **`install.sh`** installs the latest release by default; use
  `--from-source` to build a checkout. It no longer stops a running daemon.
- **`install.ps1`** installs the latest release by default; use
  `-FromSource` to build a checkout. It no longer edits your PATH in
  release mode.
- **`n` opens the new-agent page** (`new_agent_page`, on). Set it off to
  get the popup wizard back.
- **`rex daemon restart` is hot** and keeps sessions running. `-cold`
  gives the old stop and start; it asks before killing sessions, and
  without a terminal needs `-yes` (else exit 6).
- **Boards swap themselves** into a newly installed build after a minute
  idle on the board (`auto_swap`, on). Set it off to swap only with
  `:swap` or `rex upgrade`.
- **`rex reload`** also reloads `init.lua` and exits 1 when a layer failed
  to load. Scripts that ignored its errors should check the exit code.
- **Windows `.cmd` shims**: an agent installed as an npm `.cmd` shim starts
  through the program the shim runs, not `cmd.exe`. A shim rex cannot
  resolve (or a `command` that is `cmd.exe`) gets its task pasted into the
  agent, and the launch is refused unless every other argument is plain.
- **Prompt size**: the daemon refuses an initial prompt over 96 KiB
  (`bad_intent`) before spawning anything.

## Install

macOS and Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/TristanBietsch/rex/master/install.sh -o install.sh
sh install.sh                      # or: REX_VERSION=v2.0.0 sh install.sh
export PATH="$HOME/.local/bin:$PATH"
rex setup
```

The installer picks the archive for your OS and arch, checks it against
`SHA256SUMS`, and installs `rex` and `rex-daemon` into `~/.local/bin`
(`PREFIX` to change). No sudo, no shell profile edits. On Linux, sound
needs ALSA (`libasound2`).

Windows (PowerShell):

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/TristanBietsch/rex/master/install.ps1 -OutFile install.ps1
powershell -ExecutionPolicy Bypass -File .\install.ps1   # or: -Version v2.0.0
```

It checks the zip against `SHA256SUMS` and installs into `~\.local\bin`;
it prints the PATH command instead of editing PATH. Or unzip
`rex_2.0.0_windows_amd64.zip` into a folder on your `PATH`.

From v2.0.0 on, `rex update` upgrades a release install in place
(`rex update -check` only looks).

## Upgrade

**From v2.0.0 on**, upgrading keeps your sessions:

```sh
rex update        # or: sh install.sh
rex upgrade       # hot-restarts the daemon, swaps open boards
```

**The one-time switch from a pre-v2 daemon** cannot keep sessions: the
old daemon has no hot restart, so it has to stop.

1. Install v2.0.0 as above (or `git pull && ./install.sh --from-source` in
   a checkout). The running daemon and its sessions keep going on the old
   binary.
2. Let running sessions finish. Then, from a terminal outside rex (not
   inside a session, which this kills), run `rex upgrade`. It finds the
   old daemon, says so, and asks before a cold restart (`-yes` without a
   terminal). `rex daemon restart -cold` does the same.
3. Running agents end. Pick a Claude Code session up again with
   `rex resume <slug>`.
4. Quit and reopen open boards (`rex`). From now on boards swap into new
   builds by themselves.
5. Run `rex doctor`; `rex --version` prints `v2.0.0`.

`go install …@latest` users: the module path has no `/v2`, so Go ignores
the `v2.0.0` tag and builds the newest `master` commit, which is this
release. `rex update` does the same.

## Verify the download

Every archive is listed in `SHA256SUMS`:

```sh
sha256sum -c SHA256SUMS --ignore-missing     # Linux
shasum -a 256 -c SHA256SUMS --ignore-missing # macOS
```

`install.sh`, `install.ps1` and `rex update` do this for you and refuse to install on a mismatch.

Every archive and `SHA256SUMS` also carries a GitHub build provenance
attestation, which proves it was built by this repository's release
workflow from the `v2.0.0` tag:

```sh
gh attestation verify rex_2.0.0_darwin_arm64.tar.gz --repo TristanBietsch/rex
```

The
binaries are not code-signed or notarized; a macOS browser download may need
`xattr -d com.apple.quarantine rex rex-daemon`.
