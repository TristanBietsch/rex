rex v2.1.0 brings a stepped new-agent flow and a round of security
hardening: agents get an allowlisted environment, cannot drive rex
themselves, and every session records who started it.

## Highlights

- **Stepped new-agent flow**: `n` opens a full-screen page with one step
  per screen: agent, model (with effort), skills, task, context, trust,
  then a summary that shows everything the launch sends and the equivalent
  `rex new` call. `ctrl+s` launches from any step. See
  [docs/tui.md](https://github.com/TristanBietsch/rex/blob/v2.1.0/docs/tui.md#new-agent-page).
- **Agents get an allowlisted environment** (`child_env: allowlist`, the
  default): base names such as `PATH`, `HOME`, locale and proxy variables,
  the variables each tool declares in `env_pass`, your `env_passthrough`
  names, and `SSH_AUTH_SOCK` while `env_ssh_agent` is on. Keys exported in
  the shell that started rex no longer reach every agent, and the daemon
  drops them from its own environment.
- **Agents rex starts can no longer control rex.** The daemon refuses every
  intent except the Claude usage tap from a process inside one of its
  sessions (`Error` `in_session`; `rex` exits 6 there).
- **Who drove a session**: the daemon logs each connecting process and
  every intent it sends, and `meta.json` and the audit trail record
  `requested_by` (client, pid, executable). Deletes get their own audit
  line, shown by `rex audit`.
- **Terminal escapes are filtered**: `rex attach` drops clipboard, link and
  title escapes and other control strings from agents, and resets the
  terminal's modes on detach; `rex log` drops control characters.
- **The summarizer stays local**: a non-local `OLLAMA_HOST` is refused
  unless `summary_allow_remote` is on and the URL is https. `rex doctor`
  has a `summarizer endpoint` row.
- **`rex uninstall -all` removes everything rex wrote**, never following a
  symlink or junction, and lists what it keeps.
- **Unique session names**: a display name another session holds is
  refused (`name_taken`; `rex new -name` and `rex name` exit 5).
- **Summary scanner**: a band of color sweeps across the summary line
  while the selected session works or waits (`summary_scan`,
  `summary_scan_color`).
- **`filter_chips`** hides the tool filter row; `selector_glyph` gains `☛`.
- **`make update`** rebuilds a checkout and hot-switches the running daemon
  and boards; `rex upgrade -if-stale` and `-no-cold` make upgrades
  scriptable.

The full list is in [CHANGELOG.md](https://github.com/TristanBietsch/rex/blob/v2.1.0/CHANGELOG.md).

## Breaking changes and migration

- **Agents no longer inherit your whole environment.** If an agent or a
  tool lost a variable it needs (an API key, a token, a tool's own
  setting), do one of:
  - list it in `env_passthrough` (comma-separated; a trailing `*` matches a
    prefix): `rex config set env_passthrough 'GH_TOKEN,MY_TOOL_*'`;
  - add it to that tool's `env_pass` in `tools.yaml`;
  - or set `child_env: inherit` for the old behavior.

  These are trust settings: `rex config set` changes them only at a
  terminal. Then run `rex daemon restart -cold`: a hot restart keeps the
  daemon's environment, so a name added later is not there until a cold
  start.
- **`SSH_AUTH_SOCK` still reaches agents** by default. Set
  `env_ssh_agent` off to keep agents away from your SSH agent.
- **Agents cannot run `rex`.** A command an agent runs that calls `rex`
  (`rex send`, `rex ls`, `rex digest`, …) now exits 6 with `in_session`.
  Run such scripts from a terminal outside rex.
- **`rex new -trust` needs a terminal**: agent mode, `-o` and pipes exit 6
  (`needs_terminal`).
- **`REX_SESSION_ID` is gone** from agents' environment.
- **The popup wizard and `new_agent_page` are removed.** `n` and `:new`
  always open the page; a stored `new_agent_page` is ignored. The task's
  vim-style editing mode is gone too, and `enter` in the task goes to the
  next step instead of launching (`ctrl+s` launches).
- **A remote summarizer needs opting in**: with `OLLAMA_HOST` on another
  machine, set `summary_allow_remote` (terminal only) and use https.
- **Agent hyperlinks and titles** no longer reach your terminal through
  `rex attach`.
- **Duplicate session names** restored from an older daemon are kept as
  they are; new or renamed sessions must use a free name.

## Install

macOS and Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/TristanBietsch/rex/master/install.sh -o install.sh
sh install.sh                      # or: REX_VERSION=v2.1.0 sh install.sh
export PATH="$HOME/.local/bin:$PATH"
rex setup
```

The installer picks the archive for your OS and arch, checks it against
`SHA256SUMS`, and installs `rex` and `rex-daemon` into `~/.local/bin`
(`PREFIX` to change). No sudo, no shell profile edits. On Linux, sound
needs ALSA (`libasound2`).

Windows (PowerShell):

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/TristanBietsch/rex/master/install.ps1 -OutFile install.ps1
powershell -ExecutionPolicy Bypass -File .\install.ps1   # or: -Version v2.1.0
```

It checks the zip against `SHA256SUMS` and installs into `~\.local\bin`;
it prints the PATH command instead of editing PATH. Or unzip
`rex_2.1.0_windows_amd64.zip` into a folder on your `PATH`.

## Upgrade

From v2.0.0, upgrading keeps your sessions:

```sh
rex update        # or: sh install.sh
rex upgrade       # hot-restarts the daemon, swaps open boards
```

Run both from a terminal outside rex; once v2.1.0 is running, it refuses
them from inside a session.

On macOS and Linux the new daemon filters its own environment as it
starts, hot restart included. On Windows, `rex` filters the environment
when it starts the daemon, so run `rex daemon restart -cold` once (it asks
before ending running sessions).

Agents already running keep the environment they started with; new
sessions get the allowlist. Check `rex doctor`, then `rex --version`
prints `v2.1.0`.

From a pre-v2 daemon, follow the one-time switch in the
[v2.0.0 notes](v2.0.0.md#upgrade) first.

## Verify the download

Every archive is listed in `SHA256SUMS`:

```sh
sha256sum -c SHA256SUMS --ignore-missing     # Linux
shasum -a 256 -c SHA256SUMS --ignore-missing # macOS
```

`install.sh`, `install.ps1` and `rex update` do this for you and refuse to
install on a mismatch.

Every archive and `SHA256SUMS` also carries a GitHub build provenance
attestation, which proves it was built by this repository's release
workflow from the `v2.1.0` tag, and the workflow refuses tags whose commit
is not on `master`:

```sh
gh attestation verify rex_2.1.0_darwin_arm64.tar.gz --repo TristanBietsch/rex
```

A matching checksum proves the download is what GitHub published; it says
nothing about who controls the account or the workflow (see
[SECURITY.md](https://github.com/TristanBietsch/rex/blob/v2.1.0/SECURITY.md)).
The binaries are not code-signed or notarized; a macOS browser download
may need `xattr -d com.apple.quarantine rex rex-daemon`.
