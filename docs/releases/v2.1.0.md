rex v2.1.0 brings a stepped new-agent flow, a reorganized `rex --help`,
every feature on by default, and a round of security fixes. Upgrades from
v2.0.0 keep working as before: nothing you rely on is removed.

## Highlights

- **Stepped new-agent flow**: `n` opens a full-screen page with one step
  per screen: agent, model (with effort), skills, task, context, trust,
  then a summary that shows everything the launch sends and the equivalent
  `rex new` call. `ctrl+s` launches from any step. Set `new_agent_page`
  off to keep the popup wizard. See
  [docs/tui.md](https://github.com/TristanBietsch/rex/blob/v2.1.0/docs/tui.md#new-agent-page).
- **Every feature on by default**: `turn_snapshots` (`rex undo` / `redo`),
  `loops` (`rex loop`) and `workspaces` (`rex ws`) join the rest. A value
  you set in `config.yaml` or `config.lua` is kept.
- **A cleaner `rex --help`**: five groups (Start & steer, Watch, Manage,
  Daemon, Setup) under rule lines, one aligned line per command with a short
  argument hint. `rex <command> -h` uses the same layout.
- **`boot_screen`** turns the boot screen off: the startup checks still
  run, and a failed one still shows the screen.
- **Allowlisted environment for agents** (`child_env`): on a fresh install
  agents get only the base variables, each tool's own (`env_pass`) and the
  names you list in `env_passthrough`. An upgrade keeps the old behavior
  (see Upgrade).
- **Agents rex starts can no longer control rex**: the daemon refuses every
  intent except the Claude usage tap from a process inside one of its
  sessions (`Error` `in_session`; `rex` exits 6 there).
- **Who drove a session**: the daemon logs each connecting process and
  every intent it sends, and `meta.json` and the audit trail record
  `requested_by`. Deletes get their own audit line.
- **Safer defaults**: terminal escapes from agents are filtered in
  `rex attach` and `rex log`; the summarizer talks only to a local Ollama
  unless `summary_allow_remote` is on; `rex uninstall -all` removes
  everything rex wrote.
- **Unique session names**, a **summary scanner** on the board, a
  `filter_chips` switch, `☛` for `selector_glyph`, and `make update` for
  checkout installs.

The full list is in [CHANGELOG.md](https://github.com/TristanBietsch/rex/blob/v2.1.0/CHANGELOG.md).

## Security fixes that change behavior

These close holes from the security audit. They only affect agents and
scripts that relied on the hole:

- **Agents cannot run `rex`.** A command an agent runs that calls `rex`
  (`rex send`, `rex ls`, `rex digest`, …) exits 6 with `in_session`. Run
  such scripts from a terminal outside rex.
- **`rex new -trust` needs a terminal**: agent mode, `-o` and pipes exit 6
  (`needs_terminal`).
- **`REX_SESSION_ID` is gone** from agents' environment.
- **A remote summarizer needs opting in**: with `OLLAMA_HOST` on another
  machine, set `summary_allow_remote` (terminal only) and use https.
- **Agent hyperlinks and titles** no longer reach your terminal through
  `rex attach`.

## Install

macOS and Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/TristanBietsch/rex/master/install.sh -o install.sh
sh install.sh                      # or: REX_VERSION=v2.1.0 sh install.sh
export PATH="$HOME/.local/bin:$PATH"
rex setup
```

The installer picks the archive for your OS and arch, checks it against
`SHA256SUMS`, and installs `rex` and `rex-daemon` into `~/.local/bin`
(`PREFIX` to change). No sudo, no shell profile edits. On Linux, sound
needs ALSA (`libasound2`).

Windows (PowerShell):

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/TristanBietsch/rex/master/install.ps1 -OutFile install.ps1
powershell -ExecutionPolicy Bypass -File .\install.ps1   # or: -Version v2.1.0
```

It checks the zip against `SHA256SUMS` and installs into `~\.local\bin`;
it prints the PATH command instead of editing PATH. Or unzip
`rex_2.1.0_windows_amd64.zip` into a folder on your `PATH`.

## Upgrade

From v2.0.0, upgrading keeps your sessions:

```sh
rex update        # or: sh install.sh
rex upgrade       # hot-restarts the daemon, swaps open boards
```

Run both from a terminal outside rex; once v2.1.0 is running, it refuses
them from inside a session.

**Agents' environment.** The first time the v2.1.0 daemon starts where an
earlier daemon ran, it writes `child_env: inherit` to `config.yaml`, so
agents keep the full environment as before, and says so in `daemon.log`.
To turn the filter on, set it yourself:

```sh
rex config set child_env allowlist     # at a terminal
rex config set env_passthrough 'GH_TOKEN,MY_TOOL_*'   # names agents still need
rex daemon restart -cold
```

A hot restart keeps the daemon's environment, so a change to `child_env`
or `env_passthrough` reaches the daemon only after `-cold`.

**Turn snapshots** are on by default now. In a git repo, every agent turn
copies the folder's files, including untracked ones such as `.env` unless
they are gitignored, into the private store `~/.local/share/rex/snapshots`.
Set `turn_snapshots` off if you do not want that.

Check `rex doctor`, then `rex --version` prints `v2.1.0`. From a pre-v2
daemon, follow the one-time switch in the [v2.0.0 notes](v2.0.0.md#upgrade)
first.

## Verify the download

Every archive is listed in `SHA256SUMS`:

```sh
sha256sum -c SHA256SUMS --ignore-missing     # Linux
shasum -a 256 -c SHA256SUMS --ignore-missing # macOS
```

`install.sh`, `install.ps1` and `rex update` do this for you and refuse to
install on a mismatch.

Every archive and `SHA256SUMS` also carries a GitHub build provenance
attestation, which proves it was built by this repository's release
workflow from the `v2.1.0` tag, and the workflow refuses tags whose commit
is not on `master`:

```sh
gh attestation verify rex_2.1.0_darwin_arm64.tar.gz --repo TristanBietsch/rex
```

A matching checksum proves the download is what GitHub published; it says
nothing about who controls the account or the workflow (see
[SECURITY.md](https://github.com/TristanBietsch/rex/blob/v2.1.0/SECURITY.md)).
The binaries are not code-signed or notarized; a macOS browser download
may need `xattr -d com.apple.quarantine rex rex-daemon`.
