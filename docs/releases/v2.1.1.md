rex v2.1.1 makes the first prompt of a pasted session wait until the agent
is really ready, and never type it into the folder-trust dialog.

## Changes

- **The first prompt waits for the agent.** For a tool that takes its first
  prompt by paste (`prompt_paste`, such as `ollama`), the prompt is typed in
  only once the agent waits for input and its folder-trust dialog is not on
  screen: an Enter typed into the dialog would have answered it. The 30 s
  wait pauses while the dialog shows, so answering it late still delivers
  the prompt; a 10 minute cap bounds the wait.
- **A prompt that never went in says so.** The board shows `first prompt
  not delivered; paste it yourself` on that session instead of only logging
  it.
- **`prompt_paste.ready_regex`** (tools.yaml): a pattern on the agent's
  screen that says it waits for input, so a tool whose adapter cannot tell
  can take its first prompt by paste instead of on the command line, where
  every local process can read it. Claude Code still gets its first prompt
  on the command line in this release.

The full list is in [CHANGELOG.md](https://github.com/TristanBietsch/rex/blob/v2.1.1/CHANGELOG.md).

## Install

macOS and Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/TristanBietsch/rex/master/install.sh -o install.sh
sh install.sh                      # or: REX_VERSION=v2.1.1 sh install.sh
export PATH="$HOME/.local/bin:$PATH"
rex setup
```

The installer picks the archive for your OS and arch, checks it against
`SHA256SUMS`, and installs `rex` and `rex-daemon` into `~/.local/bin`
(`PREFIX` to change). No sudo, no shell profile edits. On Linux, sound
needs ALSA (`libasound2`).

Windows (PowerShell):

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/TristanBietsch/rex/master/install.ps1 -OutFile install.ps1
powershell -ExecutionPolicy Bypass -File .\install.ps1   # or: -Version v2.1.1
```

It checks the zip against `SHA256SUMS` and installs into `~\.local\bin`;
it prints the PATH command instead of editing PATH. Or unzip
`rex_2.1.1_windows_amd64.zip` into a folder on your `PATH`.

## Upgrade

From v2.1.0 or v2.0.0, upgrading keeps your sessions:

```sh
rex update        # or: sh install.sh
rex upgrade       # hot-restarts the daemon, swaps open boards
```

From v2.0.0, read the [v2.1.0 notes](v2.1.0.md#upgrade) first.

## Verify the download

Every archive is listed in `SHA256SUMS`:

```sh
sha256sum -c SHA256SUMS --ignore-missing     # Linux
shasum -a 256 -c SHA256SUMS --ignore-missing # macOS
```

`install.sh`, `install.ps1` and `rex update` do this for you and refuse to
install on a mismatch.

Every archive and `SHA256SUMS` also carries a GitHub build provenance
attestation, which proves it was built by this repository's release
workflow from the `v2.1.1` tag, and the workflow refuses tags whose commit
is not on `master`:

```sh
gh attestation verify rex_2.1.1_darwin_arm64.tar.gz --repo TristanBietsch/rex
```

A matching checksum proves the download is what GitHub published; it says
nothing about who controls the account or the workflow (see
[SECURITY.md](https://github.com/TristanBietsch/rex/blob/v2.1.1/SECURITY.md)).
The binaries are not code-signed or notarized; a macOS browser download
may need `xattr -d com.apple.quarantine rex rex-daemon`.
